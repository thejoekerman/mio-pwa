# Product and UX Decisions

- MioLog should feel companion-like but stay practical, mobile-first, and respectful of vertical space.
- Local-only users get the complete core experience.

## Navigation

- Chibi Mio in the top navigation opens `/stats`; the old `/journal` route name was misleading legacy naming.
- Bottom navigation stays a fixed custom `<nav>` with Vuetify buttons because of mobile WebKit scrolling behavior.

## Game Detail

- Journey selection in Game Overview is compact rather than presented as large cards.
- Editing clearly separates Game metadata from Journey details.

## UI Patterns

- Cover shape is a device-local Settings preference: portrait (3:4, default) or square (1:1). Shared covers and metadata suggestion previews follow it, preserving full artwork with a blurred background for mismatched proportions.

- Destructive confirms use Vuetify dialogs, not `window.confirm`.
- Duplicate-game dialogs use concise user language such as "Already in library"; users do not need implementation details about Wikidata identity.
- Settings should remain compact. Prefer sub-settings/modals over adding large panels indefinitely.

## Log Sharing

Play logs can be shared individually:
- native Web Share when available
- copy-text fallback
- configurable template in a compact Settings modal
- default template is `{title}\n\n{log}\n\n{hashtags}`
- default hashtag is `#games`
